# Data Dictionary

This describes the real, built database (see `sql/schema.sql`, owned by Member 1).
Column names here must always match that file exactly — the SQL-generation
prompt is only as correct as this document.

## customers

One row per customer.

### customer_id
Integer primary key. Uniquely identifies a customer.

### country
Country the customer is associated with.

## products

One row per stock keeping unit (SKU).

### stock_code
Text primary key. Uniquely identifies a product.

### description
Human-readable product description.

## orders

One row per invoice (order header). Represents a single transaction event.

### invoice_no
Text primary key. Uniquely identifies an order.

### customer_id
Foreign key to `customers.customer_id`. The customer who placed the order.

### invoice_date
Timestamp of the order.

### is_cancelled
1 if the order was cancelled, 0 otherwise. Cancelled orders must be excluded
from revenue, quantity and customer-activity calculations by default — see
`analytics_guidelines.md`.

## order_items

One row per line item within an order. Revenue and quantity live here, not
on `orders`.

### item_id
Auto-incrementing primary key for the line item.

### invoice_no
Foreign key to `orders.invoice_no`.

### stock_code
Foreign key to `products.stock_code`.

### quantity
Number of units purchased in this line item.

### unit_price
Price per unit for this line item.

### revenue
Revenue generated by this line item (quantity × unit_price). This is the
column all revenue KPIs sum over.

## Common joins

Almost every analytical question needs order_items joined to orders (to
reach a date or filter cancellations), and sometimes to customers or
products:

```sql
SELECT oi.revenue, o.invoice_date, o.customer_id
FROM order_items oi
JOIN orders o ON o.invoice_no = oi.invoice_no
WHERE o.is_cancelled = 0;
```

## Known limitations

- Revenue is only defined at the line-item level; there is no pre-aggregated
  per-order or per-customer revenue column, so every KPI query needs a
  `GROUP BY` and a `SUM`.
- `country` lives only on `customers`, not on each order, so a customer who
  changed country would show their current country for all historical
  orders. Not expected to occur in this static dataset.
